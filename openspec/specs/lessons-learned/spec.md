# Lessons Learned Specification

## Purpose

记录从历史变更中提取的经验教训和最佳实践,用于指导未来的变更决策。

**最后更新**: 2025-11-10
**基于数据**: 47 个归档变更

## Requirements

### Requirement: 安全相关变更需要严格审查
安全相关的变更(认证、授权、支付)MUST 包含设计文档和安全审查。

#### Scenario: 检测到安全相关变更
- **WHEN** 变更涉及认证、授权、支付、用户数据
- **THEN** 必须创建 design.md
- **AND** 必须进行安全审查
- **AND** 必须进行渗透测试

**数据支持**: 认证系统变更因缺少安全审查导致延期2天

### Requirement: 复杂变更需要分阶段实施
超过20个任务的复杂变更 SHOULD 分为多个milestone。

#### Scenario: 大型变更拆分
- **WHEN** 变更包含超过20个任务
- **THEN** 建议拆分为2-3个阶段
- **AND** 每个阶段独立可交付
- **AND** 降低集成风险

**数据支持**: 认证系统35个任务,导致12天完成(超期2天)

### Requirement: 文档任务易被遗漏
文档相关任务的完成率低于技术任务。

#### Scenario: 提高文档完成率
- **WHEN** 规划变更任务
- **THEN** 将文档任务前置到开发阶段
- **AND** 设置文档检查点
- **AND** 文档作为代码审查依据

**数据支持**: 认证系统的安全配置指南被遗漏

### Requirement: OAuth集成需要额外时间
第三方服务集成(OAuth、支付网关)需要预留额外时间。

#### Scenario: OAuth集成时间估算
- **WHEN** 估算OAuth集成时间
- **THEN** 基础时间 × 1.5倍
- **AND** 预留调试和测试时间
- **AND** 考虑第三方服务稳定性

**数据支持**: Google和GitHub OAuth集成比预期多花费1.5天

## Best Practices

1. **设计先行**: 复杂变更必须先完成设计文档
2. **小步快跑**: 单次变更控制在10-15个任务内
3. **安全优先**: 安全相关变更增加审查环节
4. **文档同步**: 文档与代码同步完成
